Multilingual Code-Smell Study

Do open-weight code models produce the code smell they are asked for, and does that depend on the language of the prompt or the programming language requested?

13 models, 22,152 Python files in four prompt languages · 5 models, 22,880 Java, C++ and C files in 4 prompt languages · source · data download

Summary

  1. Asking in another language lowers smell production. Against English, the requested smell appears 5.8 points less often in Spanish, 6.8 points less often in French and 10.7 points less often in Chinese, in every one of the 13 models. Whether the code is valid barely changes (at most 1.6 points).
  2. In Chinese, part of the drop travels with translation damage. In the Python prompts, where machine translation changed a name the prompt asked for, smell production falls 16 points; where every name survived, 8. In the Java, C++ and C prompts the pattern is not consistent: clear in 1 of 9 combinations and reversed in 1.
  3. The programming language matters smell by smell, not on average. Overall, Java, C++ and C are at most 4.1 points from Python (Java +4.1, C++ +2.2 and C +2.3, every model leaning the same way); smell by smell they differ by up to 54 points, following each language's habits.
  4. The prompt-language effect holds in every programming language. Against English, smell production falls in 12 of the 12 combinations of prompt and programming language, every one beyond noise, with all 5 models agreeing in 11; Chinese costs most, 12.3 to 14.1 points in Java, C++ and C. It is a little larger than in Python for French in Java and Chinese in Java and C++, though only the mixed model puts that beyond noise.
  5. C and C++ produce less valid code because of one model, and only in English. granite-8b-code writes #include lines that name no header in 54% of its English C++ and 55% of its English C answers, and almost never when the prompt is in Spanish, French or Chinese; no other model does this at all.

Restricted to the smells whose detectors discriminate well (a lift of at least 20, below), the changes are −5.8 in Spanish, −6.7 in French and −10.9 in Chinese, so the weak detectors are not what carries the effect.

Valid code barely depends on the prompt language. Where it dips, the model is mostly declining the task rather than writing broken code: 92 of the 5,538 Spanish replies are refusals (“Lo siento, pero no puedo ayudarte con eso”), against 4 in English, most of them from deepseek-coder-6.7b, deepseek-coder-1.3b, qwen2.5-coder-3b and qwen2.5-coder-7b.

Code quality does not depend on the prompt language: on files that parse, 5.1 to 6.3 lint violations per 100 lines in all four. Files that fail to parse average 69 per 100 lines, which is why quality is only measured on parsing files.

Experiment 2 · programming language

The English prompts ported to Java, C++ and C, asked of 5 models: one dense model of 7 to 9 billion parameters from each of 5 families. C is asked 292 of the 426 prompts because 8 smells are defined over classes; each comparison uses the prompts asked in both languages.

The C and C++ validity gap is one model. granite-8b-code writes valid C++ 43% and C 43% of the time, against 95% in Python. In 54% of its C++ and 55% of its C answers it writes #include lines that name no header, which no compiler accepts, and in 35% and 47% it repeats that line until the output limit. The other 4 models stay between 96.9 and 99.8% in every language. Separately, starcoder2-7b never stops by itself and reaches the output limit on every answer in every language, but its answer comes first, so 98 to 99% of its files still parse.

Smells follow each language's habits

The average hides large differences smell by smell, and the direction is consistent: a smell is easier to produce where it is the ordinary way to write that language.

  • Data Class (Java 96.2%, Python 42.5%). A class of private fields with getters and setters is how Java ordinarily stores data, so a model writes a textbook example; Python has several competing conventions, so fewer answers match the definition.
  • Long Parameter List (Python 100.0%, C 73.8%). C and C++ programmers usually pass a struct rather than many separate arguments.
  • Global State (C 97.4%, Java 71.8%). A variable at file level is ordinary C, while Java makes the model reach deliberately for a static field.

Experiment 3 · both languages at once

The Java, C++ and C prompts translated into Spanish, French and Chinese the same way as the Python ones, and asked of the same 5 models, so every prompt language meets every programming language.

Compared with Python, the French drop in Java and the Chinese drop in Java and C++ are a little larger, by 2.6 to 4.2 points; the paired intervals include zero, and only the mixed model, which assumes one effect for every prompt and so gives narrower intervals, puts them beyond noise. How the numbers were produced

  • Generation. Oxford's ARC GPU cluster, one prompt at a time, greedy decoding, up to 2,048 new tokens, bfloat16 throughout. An answer is exactly reproducible on one machine; across GPU nodes a small share differ, enough to flip the parse verdict for about 7% of prompts in a CodeLlama comparison.
  • Prompts. Spanish, French and Chinese by NLLB-200 machine translation, with system prompts translated by hand. Java, C++ and C ported rather than translated, since "write a Python function" has to become "write a Java method"; 23 prompts were rewritten by hand. The ported prompts were then translated exactly as the Python ones were.
  • Extracting the code. The answer is the first fenced code block in the requested language. A reply with no fence is taken whole if it parses; otherwise the code is recovered from between the prose. The system prompt asks for no Markdown, yet 12 of the 13 models fence their English code anyway. Against the first version of the extractor, which joined every block and required a fence, smell production moves by at most 1.0 points in any language; validity moves by 5 points or more in 16 model-and-language cells, belonging to granite-3b-code, granite-8b-code and starcoder2-7b (extraction_check.csv lists them).
  • Detectors. Experiment 1 uses the Python detector, 21 of 25 smells, built on Python's own parser. Experiments 2 and 3 use one tree-sitter detector for all four languages, 12 of 25 smells, so each smell has a single definition; Python is re-scored with it so the columns share an instrument.
  • Uncertainty. Each difference is recomputed in 1,000 resamples of whole prompts, because one prompt's files rise and fall together. As a check, a logistic mixed-effects model with crossed random intercepts for prompt and model (mixed_model.csv) agrees on the direction of every effect; its odds ratios against English are 0.65 in Spanish, 0.60 in French and 0.45 in Chinese. Because it assumes one effect for every prompt, its intervals are narrower: it puts Java and C above Python, which the resampling does not.
  • Excluded. mamba-codestral-7b substitutes a wrong token about once in every 140 and only 6 of 20 files parse. Five causes were tested: two were pipeline faults and were fixed, three were ruled out, leaving the published model itself. The release notes record what was tested.
